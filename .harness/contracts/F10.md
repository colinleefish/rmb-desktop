- **Feature ID**: F10 (feature_list.json)
- **Issue**: — (dev tooling, no user-facing bug; requested directly by the owner)

- **Date**: 2026-09-12

## Scope

**In** (this contract delivers):
- Central mock flag (`VITE_MOCK=true` env or `localStorage.rmb.mock`, dev build only) that puts the whole webui in mock mode — existing per-feature flags (`VITE_MOCK_SETUP/PIPELINE/ONBOARDING`) automatically honor it.
- In-memory mock API router covering every endpoint the SPA calls: browse overview / pipeline-health / sessions (paging, q, sort) / session detail (turns, atoms, scenes, pipeline state) / memories (paging, category) / skills (paging, detail with file tree) / corrections (list/create/retract) / config (GET/PUT) / version / system restart + healthz phases / config test (llm+embed) / onboarding status/complete/reset.
- Rich deterministic mock dataset (seeded PRNG): ~36 sessions across agent sources with realistic rmb-domain turns/atoms/scenes, ~60 memories across the 4 categories with recall stats, 12 skills with file trees, corrections, pipeline health consistent with overview counts.
- `MOCK` badge in the corner while mock mode is on; in localStorage mode it is clickable to toggle back to the proxied real daemon (reload).
- Vite dev proxy target env-configurable: `RMB_API_TARGET` (default stays `http://127.0.0.1:19019`); `npm run dev` remains the real-data mode, new `npm run dev:mock` the mock mode.

**Out** (explicitly excluded):
- No changes to the Go daemon, HTTP handlers, or embedded static serving (`internal/http/static/web/` untouched).
- No new npm dependencies (hand-rolled router, matching the existing `*Mock.ts` convention — no MSW).
- No redesign of existing per-feature mocks (`setupApiMock`, `overviewMock`, `pipelineHealthMock`, `onboardingApiMock`) — they keep their stories and are reused as-is.
- No test runner/vitest addition; router contract pinned by an esbuild-bundled node selftest instead.

## Definition of Done

The feature's `layers` in `feature_list.json` (L1 static / L2 runtime / L3 system) all pass via
`make verify-feature F=F10`. Runtime acceptance: `cd webui && npm run dev:mock` serves Overview,
Sessions (+detail), Memories, Skills (+detail), Integrations, Settings against mock data with no
daemon running; `npm run dev` against the running daemon shows real data.

## Risks / open questions

- Mock fetch interception sits in the api helpers (not `window.fetch`), so any future direct `fetch` outside those helpers must add a guard — noted in code comments.
- Owner said "proxy to localhost:19090"; the daemon's real port is 19019 (`internal/config` DefaultAddr). Proxy stays 19019 by default, overridable via `RMB_API_TARGET`, so either way works.
