# Sprint Contract — F13: intel-dmg-build

- **Feature ID**: F13 (feature_list.json)
- **Issue**: —
- **Branch / worktree**: `feat/intel-dmg-build` / `../rmb-desktop-intel-dmg`
- **Date**: 2026-09-19

## Scope

**In** (this contract delivers):
- `make build-intel`: cross-compile `bin/intel/{rmb,rmbd,rmb-app}` as darwin/amd64
  (cgo, `-arch x86_64`, minos ≤ `MACOSX_DEPLOYMENT_TARGET`).
- `make app-build-intel`: assemble the .app under `dist/intel/` (env-parameterized
  `build-macos-app.sh`) and produce `dist/RMB Desktop_<VERSION>_amd64.dmg`
  (`build-dmg.sh` gains an arch argument; default stays `aarch64`).
- Arm64 pipeline outputs (`bin/`, `dist/RMB Desktop.app`, `_aarch64.dmg`) untouched.

**Out** (explicitly excluded — do not touch):
- `make release` / `scripts/release.sh`: the Intel DMG is a local one-off, not part of
  the signed release matrix this session.
- Updater: `manifest.json` still ships `macos.aarch64` sidecars only — on Intel the
  self-updater will find no `macos.amd64` entry and must not self-update.
- Notarization: no `~/.rmb/release.env` in this session → ad-hoc codesign only
  (Developer ID signing works if `SIGN_KEYCHAIN_PASS` is provided at build time).
- Any lowering of `MACOSX_DEPLOYMENT_TARGET` / `LSMinimumSystemVersion` below 13.0
  (Go 1.27's Darwin floor).

## Definition of Done

The feature's `layers` in `feature_list.json` (L1 static / L2 runtime / L3 system) all pass via
`make verify-feature F=F13`. No hand waved completion: state moves to `passing` only with evidence.

## Risks / open questions

- "Old" Intel MacBooks still need macOS 13 Ventura+ (Go 1.27 toolchain floor); machines
  stuck on Monterey 12 or older cannot launch the binaries, and that is not fixable here.
- Ad-hoc signing: a DMG copied via browser download gets quarantined on the target Mac —
  transfer via USB/LAN or run `xattr -dr com.apple.quarantine` on the .app.
- Updater gap: Intel installs won't receive auto-updates until amd64 sidecars + manifest
  entries ship in a real release.
